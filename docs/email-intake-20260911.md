# 이메일 수령 접수 — 2026-09-11

기존 검토 브랜치의 웹 접수 안정화 위에 적용한 변경이다. 운영 배포 전 새 Apps Script와 함께 연결 검증해야 한다.

## 고객 흐름

1. 병원과 서류를 선택한다. 기본 수령 방법은 이메일이며 원본·영상CD 등기는 기존 20,000원 추가 요금을 유지한다.
2. 기존 환자 정보를 입력하고 연락받을 휴대폰과 이메일을 확인한다. 휴대폰은 환자 연락처와 같음이 기본이며 다른 신청인에게 연락하려면 별도 번호를 입력한다. 환자 연락처는 덮어쓰지 않는다. 등기 수령이면 이메일은 선택사항이다.
3. 신분증과 서명을 제출한다. 서명 화면에서 문자 받을 번호와 수령 주소를 다시 확인하며, 별도 확인 단계를 추가하지 않는다.
4. 저장을 확인한 뒤 서버의 주문번호와 대행료를 표시한다. 병원 발급 비용은 문자, 최종 파일은 신청한 이메일로 안내한다. 카카오톡 링크는 문의·긴급 연락용이다.

## 서버 계약

기존 `action: sendMail` 필드를 유지하고 `schemaVersion: 2`, `contactPhone`, `email`, `deliveryMethod: email | post`를 보낸다. `patientPhone`과 기존 환자·병원·서명·신분증 필드는 유지한다. 문자 연락처는 숫자만, 이메일은 앞뒤 공백을 제거하여 보낸다.

성공 응답은 다음을 모두 충족해야 한다.

- `ok: true`, 요청과 같은 `orderId`, 비어 있지 않은 문자열 `receiptNo`
- 양의 안전한 정수 `baseAmount`
- `state`: `waiting_payment`, `paid`, `delivered`, `cancelled` 중 하나

`waiting_payment`일 때만 계좌를 안내한다. 다른 상태의 중복 응답에서 대행료 입금을 다시 유도하지 않는다. 응답이 구형 `{ok:true}`이거나 내용이 맞지 않으면 입력과 서명을 보존하고 접수 결과 미확인으로 안내한다. 같은 열린 페이지에서 재시도할 때 원래 주문번호를 유지하며 자동 재전송하지 않는다. 서버에서도 같은 주문번호의 변경된 내용은 충돌로 거부해야 한다.

서버가 저장 전에 입력 검증만 실패했다고 `{ok:false,code:validation,error}`로 확정하면 해당 필드의 수정 안내만 보여주고 사진·서명을 유지한다. 일반 실패나 네트워크 오류는 계속 접수 결과 미확인으로 취급한다. 앞선 전송 결과가 이미 미확인이었던 경우에는 이후 검증 오류가 와도 원래 주문번호와 접수 확인 안내를 유지한다.

이전의 다른 입금자 이름을 입력한 뒤 다시 ‘신청인과 같음’을 선택하면, 숨겨진 이전 이름 대신 현재 신청인 이름을 보내도록 수정했다.

# 서류대리님 신청 웹 점검 · 2026-11-23

운영 기준 커밋은 `c3104d638d0814e10590ee8ec38abe39a78529fc`다. 점검 당시 Netlify가 삽입한 코드와 공백을 제외하면 운영 HTML은 해당 커밋과 일치했다. 검토 후보는 로컬에 보관했다. 운영 배포는 승인 대기다.

## 고객 화면

- 첫 화면에 서울·경기, 정신과 진료기록 제외, 병원 한 곳 대행료 25,000원, 서류 발행비 별도, 처리기간 1~5영업일을 표시한다. 이용 안내는 펼쳐 본다.
- 신청은 병원·서류·수령 방법, 연락처·신분증·서명의 두 화면을 사용한다. 한 병원, 전체 기간, 이메일 수령이 기본이다. 추가 병원과 빠른 등기를 선택하면 합계를 갱신한다. 주요 입력 오류는 해당 칸에 표시하고 포커스를 이동한다.
- 제목은 배민 주아체, 본문은 배민 한나체 Air를 사용한다. 주요 글씨를 약 1px 키웠다. 웹폰트·서명 라이브러리·아이콘을 사이트에 포함해 외부 CDN에 대한 초기 요청 세 개를 제거했다. 봉투 사진은 캐시할 수 있는 별도 JPEG로 분리했다.
- 입금 안내에는 금액·계좌번호·복사 버튼·주문번호가 보인다. 발급비 링크의 금액이 올바르지 않으면 문의 안내가 열린다.

## 접수 및 검색

- 같은 시각에 시작한 신청을 구분하고, 결과가 불확실한 재시도에는 기존 주문번호를 사용한다. 접수 시점의 병원·이름·사진을 같은 주문에 묶는다.
- 병원 검색이 지연되면 직접 입력을 선택할 수 있다. 잘못된 검색 레코드가 정상 결과를 가리지 않도록 했다. 검색어가 바뀌면 이전 결과와 주소를 초기화한다.
- 사진은 서버가 받는 JPEG·PNG 및 4MiB 상한을 적용한다. 필요한 사진만 변환하며 이름 인식에는 원본을 사용한다. 한국 이름 앞부분이 지명과 같을 때의 판독을 보완했다.
- 여러 병원의 서류 요청이 길어도 병원별 입력을 보존하며 이전 방식의 요약 필드만 서버 상한에 맞춘다. 사용하지 않는 신청 화면과 관련 코드·스타일을 정리했다.

## 업무 흐름 확인

- 웹 접수 직후 운영자 텔레그램에 환자명·입금자명·병원·대행료·주문번호와 입금 확인 버튼이 전달되는 구조다. 운영자가 계좌 입금을 확인하고 누르면 접수 상세와 병원 방문용 HWPX가 별도 메시지로 전달된다. 파일에는 환자명과 주문번호가 캡션으로 붙는다. 병원에서 발급한 기록은 이메일·등기로 전달한다.
- 11월 15일 설치 기록과 9월 22일 보관된 서류 생성 엔진의 SHA-256이 일치했다. 11월 23일 별도 제작한 서류봇은 수동 작성·로컬 저장 프로그램이다. 웹 신청 대기열 및 텔레그램 자동 전달은 기존 엔진이 담당한다.
- 보관된 GAS 구현에서 시트는 입금 상태·문서 대기열·최종 발송 처리에 쓰인다. 현금영수증용 장부에는 거래일자·성명·대행료·휴대폰·주문번호를 남긴다.
- 9월 22일 v73 서버 소스는 환자와 입금자 이름이 다르면 거절한다. 10월 8일 웹은 별도 입금자를 허용하도록 변경됐다. 현재 운영 GAS 원문을 대조하지 못해, 별도 입금자 허용 수정안은 비공개 배포 후보로 분리했다. 같은 수정이 이미 적용됐는지 운영 원문을 먼저 대조한다.

## 검증 범위

- 웹 회귀 검사는 `node --test tests/*.test.cjs`로 실행해 137개 모두 통과했다. DOM·파일·서버 응답은 합성 데이터다.
- 모바일 너비 320px와 390px의 브라우저 미리보기에서 신청 진입, 빈 필드 강조와 포커스, 병원 추가·삭제와 금액, 검색 실패 시 직접 입력, 등기 주소 표시, 다른 입금자 입력, 단계 복귀 시 값 유지, 발급비 화면을 확인했다. 병원 두 곳과 등기 선택 시 70,000원이 표시됐다.
- v73 원본과 수정안을 로컬에서 대조했다. 동일·별도 입금자, 환자명 확인, 이름 응답과 장부 기록, 중복 입금 확인, 연락처를 모르는 별도 입금자의 영수증 대기를 확인했다. 기존 PC 엔진으로 가상 병원 두 곳의 HWPX를 실제 생성했다.
- 운영 GAS 상태 응답과 병원 검색의 정상 응답을 각각 확인했다. 현재 운영 GAS 원문, 당일 PC 프로세스와 실제 텔레그램 수신·고객 발송은 미검증 상태다.
